# ShortsVideoMaker

Два инструмента для нарезки коротких вертикальных клипов из фильмов, сериалов
и мультфильмов — с субтитрами и караоке-подсветкой активного слова.

| | Для чего | Где работает |
|---|---|---|
| **Веб-редактор** — `index.html` | Нарезать видео на несколько клипов, вручную выверить каждую границу, поправить субтитры и выгрузить всё пачкой | Прямо в браузере, ничего ставить не нужно → **https://mokydek.github.io/ShortsVideoMaker/** |
| **Конвейер** — `autocut.py` | Прогнать **целый фильм** без участия человека и залить результат на YouTube и в TikTok | Python + ffmpeg на вашем компьютере |

Инструменты дополняют друг друга: конвейер молотит длинный фильм пачкой без
присмотра, редактор даёт полный ручной контроль и не требует вообще ничего
устанавливать.

---

# Часть 1. Веб-редактор

**Открыть: https://mokydek.github.io/ShortsVideoMaker/**

Всё работает **прямо в браузере**: видео обрабатывается на вашем компьютере и
никуда не загружается. Ни сервера, ни регистрации, ни установки программ.

## Что умеет

| | |
|---|---|
| **Загрузка** | Кнопкой, перетаскиванием или **по прямой ссылке** на файл — её можно вставить в поле, кинуть на страницу или просто нажать Ctrl+V. Если браузер не умеет открывать файл — сразу честно об этом скажет. |
| **Сразу много файлов** | Можно скормить хоть весь сезон: приложение разберёт каждый файл и будет держать их все. Клип помнит, из какой серии вырезан, и при переключении на него видео подменяется само. |
| **Автоподбор моментов** | «🤖 Собрать лучшие моменты» сам находит по звуку места, где больше речи, громче и живее, и делает из них клипы — с подписью, чем каждый приглянулся. Ищет **сразу по всем загруженным файлам**: если одна серия живее остальных, оттуда возьмётся больше. Можно сразу распознать в них речь. |
| **Много клипов сразу** | Из одного видео получается сколько угодно клипов. «✂ Нарезать всё подряд» делит его одним нажатием, «＋ Вручную» берёт кусок сами. Клипы можно копировать и удалять, на таймлайне видно все сразу. |
| **Нарезка по паузам** | Границы ставятся **в тишине между фразами**, а не просто по секундомеру — реплика не оборвётся на середине. Работает так же, как в конвейере, но прямо в браузере. |
| **Волна звука** | На таймлайне нарисована громкость: сразу видно, где речь, а где пауза. Паузы отмечены зелёной полоской снизу. |
| **Обрезка** | Кнопки «Начало здесь» / «Конец здесь», точная подстройка числами, **перетаскивание границ мышью** прямо на таймлайне, кнопка «Прослушать клип». |
| **Отмена** | <kbd>Ctrl</kbd>+<kbd>Z</kbd> и <kbd>Ctrl</kbd>+<kbd>Y</kbd> — удалённый клип и стёртые субтитры возвращаются вместе с уже отрендеренным файлом. |
| **Горячие клавиши** | Пробел, <kbd>I</kbd>/<kbd>O</kbd> — границы, <kbd>J</kbd>/<kbd>L</kbd> — ±5 секунд, стрелки — по кадру, <kbd>N</kbd> — новый клип, цифры — выбор клипа. Список раскрывается под плеером. |
| **Кадрирование** | Три режима: **9:16 обрезкой** (края теряются), **9:16 с размытым фоном** (кадр виден целиком, пустое место занимает размытая копия — вместо чёрных полос) и исходный формат. Ползунок запоминается для каждого клипа свой. |
| **Чёрные поля** | Если в исходнике вшиты чёрные полосы (широкий фильм в кадре 16:9), приложение находит их само по нескольким кадрам и работает по картинке внутри — полосы не поедут в клип. Отключается галочкой. |
| **Цензура кадра** | Приглушает кровь и жёсткие сцены: кадр обесцвечивается или размывается. Срабатывает само по доле красного в кадре либо включается на весь клип. Субтитры и плашки остаются цветными. |
| **Автосубтитры** | Распознавание речи моделью **Whisper** прямо в браузере (transformers.js). На выбор tiny / base / small, язык — авто, русский или английский. Можно распознать один клип или сразу все. |
| **Пометки звуков** | В паузах, где звук есть, а слов нет, появляется **[СМЕХ]** или **[МУЗЫКА]**. Смех отличается от музыки по «рваности» громкости — несколько всплесков в секунду. Отдельной строкой, а не вперемешку со словами. |
| **Редактор** | Список реплик: правится время начала, время конца и текст; строки можно добавлять и удалять. Реплики группируются по 3–4 слова — как в TikTok. У каждого клипа свои субтитры. |
| **Стиль** | Готовые пресеты **TikTok / YouTube / Минимал / Неон** в одно нажатие, дальше — размер, положение, цвет текста, цвет подсветки активного слова, подложка, ЗАГЛАВНЫЕ. Общий для всех клипов, чтобы серия выглядела одинаково. |
| **Подпись источника** | Мелкая строка у края кадра с автором и названием — то, чего ждут от цитирования и обзора. Вшивается в клип вместе с субтитрами. |
| **Экспорт пачкой** | «🎬 Все по отдельности» ставит клипы в очередь и пишет по одному. Готовое скачивается по одному или **одним ZIP-архивом**. |
| **Склейка в один ролик** | «🎞 Склеить в один» пишет все клипы подряд в один файл — с переходами (наплыв, затемнение, вспышка) и движением в кадре (плавный наезд или толчок в начале). Это и есть монтаж «эдита». |
| **Топ-подборка** | «🏆 Топ-подборка» делает ролик формата «Топ 5 моментов»: номер места и название на каждом клипе, обратный отсчёт 5→1 и заставка с заголовком в начале. |

## Как открыть локально

Скачайте репозиторий и **дважды щёлкните по `index.html`** — этого достаточно.

Единственный нюанс: при открытии через `file://` некоторые браузеры не дают
загрузить модель распознавания речи с CDN. Всё остальное работает и так. Если
нужны автосубтитры, поднимите локальный сервер:

```bash
python -m http.server 8000
```

и откройте `http://localhost:8000/`.

## Как устроено

Один файл `index.html` — HTML, CSS и JavaScript инлайном. Внешняя зависимость
ровно одна: [transformers.js](https://github.com/huggingface/transformers.js) с
CDN jsDelivr, и она нужна только для распознавания речи.

1. **Звук.** Основной путь — разобрать файл целиком через `OfflineAudioContext`
   с частотой 16 кГц и вырезать нужный кусок: получается мгновенно и без
   потерь. Разобранный звук сводится в моно и хранится 16-битным — трёхчасовой
   фильм занимает около 345 МБ вместо полутора гигабайт, а распознаванию
   точности хватает с запасом (Whisper всё равно работает с моно 16 кГц).
   Пределы: **до 2 ГБ и до 3 часов**. Если файл больше, памяти не хватило или
   браузер не смог разобрать контейнер, включается запасной путь — захват в
   реальном времени через `MediaElementSource` → `AudioWorklet`, с
   проигрыванием в 2× или 4× и отключённым `preservesPitch` (сэмплы читаются
   как поток с частотой `sampleRate / speed`, поэтому темп и тон возвращаются
   к исходным).
2. **Проверка звука и волна.** По огибающей громкости считаются фон и уровень
   речи. Тот же разбор идёт по всему ролику: получается волна на таймлайне и
   список пауз, по которым ставятся границы клипов. Если попались целые пустые
   кадры — значит захват потерял куски звука, и приложение переснимает на
   меньшей скорости. Если звука нет вовсе, оно честно говорит об этом, а не
   запускает распознавание впустую.
3. **Распознавание.** Whisper через ONNX Runtime Web. Запрашиваются пословные
   тайминги (`return_timestamps: 'word'`) — ради них берутся сборки
   `onnx-community/whisper-*_timestamped`, у которых в ONNX выгружено
   кросс-внимание декодера. Если их нет, приложение переходит на посегментные
   метки и раскладывает слова внутри сегмента равномерно.
4. **Чистка.** Whisper любит дописывать текст поверх тишины — обычно это хвосты
   ютубовских титров («Продолжение следует…», «Субтитры сделал…», «Thanks for
   watching»). Слова, попавшие на тишину, выбрасываются по той же огибающей
   громкости, а зацикленные повторы одной реплики схлопываются.
5. **Экспорт.** Видео проигрывается в реальном времени, каждый кадр рисуется на
   canvas с обрезкой и субтитрами, `canvas.captureStream()` и
   `MediaStreamDestination` собираются в поток и пишутся `MediaRecorder`.
   Несколько клипов пишутся строго по очереди — поделить видеоэлемент между
   ними всё равно нельзя.
6. **Архив.** ZIP собирается прямо в браузере, без сжатия (видео уже сжато) и
   без сторонних библиотек — так страница остаётся полностью офлайновой.

## Цензура жёстких кадров

Галочка **«Цензура: приглушать кровь и жёсткие кадры»** в разделе
«Кадрирование». Кадр либо **обесцвечивается**, либо **размывается**, либо и то
и другое. Субтитры, плашки мест и подпись источника при этом остаются
цветными и читаемыми — эффект ложится только на картинку.

**Когда включать:**

* **Само, по красному в кадре** — приложение считает долю «кровавых» пикселей
  (тёмно-красных, резко отличающихся от зелёного и синего) на уменьшенной
  копии кадра и включает эффект, когда она переходит порог. Есть гистерезис и
  плавный переход, поэтому на границе не мигает.
* **Весь клип** — эффект держится постоянно, без определения.

Ползунок чувствительности задаёт порог: сколько красного в кадре считать
поводом. По умолчанию 6% площади.

**Честно про ограничения.** Это оценка по цвету, а не понимание картинки.
Красная одежда, закат, вывеска или логотип тоже её включат, а кровь в тёмной
сцене или синеватой цветокоррекции может не набрать порога. Если материал
такой — надёжнее поставить «весь клип» и не полагаться на автоматику.

## Чтобы не было чёрных полос

Горизонтальное видео в вертикальной ленте площадка показывает с чёрными
полосами сверху и снизу. Обойти это можно двумя способами, и оба есть в
приложении.

**9:16 обрезкой** — из широкого кадра вырезается вертикальная полоса. Кадр
занимает экран целиком, но края теряются: если в них происходит что-то важное,
это не подходит.

**9:16 с размытым фоном** — кадр вписывается целиком, ничего не отрезается, а
пустое место сверху и снизу занимает размытая и приглушённая копия того же
кадра. Так обычно и оформляют горизонтальные ролики для Shorts и Reels.
Ползунок двигает основной кадр по вертикали (удобно поднять его повыше, чтобы
освободить место под субтитры), второй ползунок меняет силу размытия.

Отдельно приложение проверяет, нет ли чёрных полос **внутри самого исходника** —
так бывает с широкоэкранными фильмами, записанными в кадр 16:9. Оно смотрит
несколько кадров в разных местах ролика и считает полем только то, что чёрное
на всех сразу (иначе тёмная сцена сошла бы за полосу). Найденное показывается
рядом с галочкой, и дальше все режимы работают уже по картинке без полос.

## Загрузка по ссылке — что работает, а что нет

Ссылку можно вставить в поле под кнопкой выбора файла, перетащить прямо на
страницу или нажать <kbd>Ctrl</kbd>+<kbd>V</kbd> где угодно на сайте. Скачанное
видео дальше ничем не отличается от выбранного с диска: оно остаётся в памяти
вкладки и никуда не отправляется.

**Работает** прямая ссылка на сам файл — такая, которая заканчивается на `.mp4`,
`.webm` или `.mov`, и сервер при этом разрешает читать файл со стороннего сайта
(заголовок `Access-Control-Allow-Origin`). Так отдают файлы многие облачные
хранилища и собственные сайты.

**Не работает** ссылка на страницу с плеером — YouTube, TikTok, Instagram,
ВКонтакте, Rutube, Vimeo и подобные. Это не недоработка: площадки отдают видео
своему плееру по частям и намеренно не разрешают читать файл со стороны.
Обходить их защиту приложение не будет — это нарушало бы условия использования
этих сервисов, а часто и авторские права. Приложение просто скажет, что так
нельзя, и предложит перетащить файл.

**Не работает** и обычная ссылка на файл, если сервер не разрешает чтение со
стороннего сайта. Это ограничение того сервера, из браузера его не обойти.
В этом случае проще всего скачать файл и перетащить его сюда — приложение об
этом и напишет.

## Несколько файлов сразу

Выберите или перетащите хоть весь сезон — приложение разберёт каждый файл по
очереди и оставит их все в списке под кнопкой загрузки. Кнопка **«＋ Ещё
файлы»** дописывает файлы к уже загруженным, не трогая проделанную работу;
выбор через основную кнопку начинает заново.

Каждый клип помнит, из какой серии он вырезан. Когда вы выбираете такой клип
или отправляете его на экспорт, приложение само подменяет видео в плеере — это
занимает секунду. В списке клипов рядом с каждым написано имя файла-источника.

Файл, из которого уже нарезаны клипы, удалить нельзя — сначала удалите сами
клипы, иначе они остались бы без исходника.

## Автоподбор моментов

Кнопка **«🤖 Собрать лучшие моменты»** делает всё сама: берёт уже разобранную
картину громкости, оценивает каждое возможное окно и отбирает лучшие
непересекающиеся, подтягивая границы к паузам. Если файлов загружено
несколько, окна со всех соревнуются в одном списке — из более живой серии
возьмётся больше кусков.

Оценивается три вещи: **сколько там речи** (доля громких кадров), **насколько
громко** и **насколько «рвано»** звучит — рваность выдаёт смех, реакции и
перебивки. Режим в выпадающем списке меняет веса: «Больше речи» тянет к
разговорным местам, «Громкие сцены» — к громким, «Смех и реакции» — к
всплескам. Рядом с каждым клипом пишется, чем он приглянулся: «плотная речь»,
«живая реакция», «громкая сцена».

Галочка «Сразу распознать речь» тут же прогоняет по выбранным клипам Whisper,
так что через несколько минут получается готовая пачка с субтитрами.

**Чего это не делает:** приложение не понимает смысла происходящего. Оно не
отличит удачную шутку от громкой рекламы и не знает, чем закончится сцена.
Это подсказка по звуку — она хорошо находит места, где «что-то происходит»,
но итог всё равно стоит просмотреть и подвинуть границы.

Проверялось так: собран ролик, в котором заранее известно, где интересные
места (30–50, 90–110 и 150–170 секунда), остальное — тишина. Подборщик выбрал
30–48, 90–108 и 150–168.

## Топ-подборка («Топ 5 моментов»)

Кнопка **«🏆 Топ-подборка»** в разделе «Клипы» превращает набор клипов в
готовый ролик формата «Топ N». Каждый клип получает номер места и название,
которые вшиваются в кадр плашкой сверху.

* **Порядок** — обратный отсчёт (5 → 1) или прямой. Обратный ставится по
  умолчанию: так досматривают до конца ради первого места.
* **Заголовок** подставляется сам по числу клипов («Топ 5 моментов»), его
  можно переписать.
* **Заставка** — в начале склеенного ролика, поверх размытого первого кадра.
  По умолчанию показывает **весь список сразу**, строки проявляются одна за
  другой:

  ```
  Топ 5 моментов
  1) Название
  2) Название
  3) Название
  4) Название
  5) Название
  ```

  Номер выделен цветом, название белым. Размер подбирается сам, чтобы список
  любой длины поместился в кадр, а длинные названия переносятся по словам.
  Галочка «Показать весь список» отключает, оставляя один заголовок; ноль
  секунд убирает заставку целиком.
* **Название места** вводится в разделе «Границы клипа» для выбранного клипа.
* **Показывать место, сек** — ноль оставляет плашку на весь клип, иначе она
  пропадает через заданное время.

Порядок мест считается от позиции клипа в списке, так что переставить их
местами — это просто удалить и добавить заново либо подвинуть границы.
Дальше жмёте **«🎞 Склеить в один»** и получаете готовый ролик одним файлом.

## Склейка в один ролик

Кнопка **«🎞 Склеить в один»** пишет все клипы подряд в один файл, в том
порядке, в каком они стоят в списке. Между клипами запись ставится на паузу,
поэтому перемотка и подмена файла в результат не попадают — куски стыкуются
встык.

**Переходы:** наплыв (предыдущий кадр растворяется в следующем), затемнение,
вспышка или встык без перехода. Длина перехода настраивается и сама
укорачивается, если клип слишком короткий.

**Движение в кадре:** плавный наезд на протяжении клипа, резкий толчок в
начале, либо чередование через клип. Так статичная нарезка выглядит живее.

Галочку «Оставить звук из клипов» стоит снять, если поверх пойдёт своя
музыка — на стыках звук всё равно рвётся, и чаще его заменяют целиком.

## Как нарезать пачку клипов

1. Загрузите видео. Пока вы смотрите на него, приложение разберёт звук и
   нарисует волну на таймлайне — по ней видно, где речь, а где паузы.
2. Нажмите **«✂ Нарезать всё видео»**, задайте желаемую длину части. Галочка
   «резать только в паузах речи» стоит по умолчанию: границы встанут в тишине
   между фразами, а не посреди слова. Под кнопкой сразу видно, сколько клипов
   получится.
3. Пройдитесь по списку: клик по клипу выбирает его, дальше правьте границы,
   сдвиг кадра и субтитры именно для него. Границы удобно двигать прямо на
   таймлайне за фиолетовые ручки. Ошиблись — <kbd>Ctrl</kbd>+<kbd>Z</kbd>.
4. **«✨ Во всех клипах»** распознаёт речь по очереди во всех сразу.
5. **«🎬 Все клипы»** ставит экспорт в очередь. Готовые помечаются зелёной
   точкой, и внизу появляется **«📦 Скачать все архивом»**.

Всё это делается и с клавиатуры: <kbd>I</kbd> и <kbd>O</kbd> ставят границы по
текущему кадру, <kbd>N</kbd> создаёт клип, <kbd>C</kbd> проигрывает выбранный,
цифры <kbd>1</kbd>…<kbd>9</kbd> переключают клипы. Полный список раскрывается
под плеером.

## Ограничения веб-редактора

* **Экспорт идёт в реальном времени.** 30 секунд клипа ≈ 30 секунд ожидания,
  и клипы пишутся по одному: десять клипов по минуте — это десять минут.
  Не сворачивайте вкладку во время записи. Если нужно обработать целый фильм
  без присмотра, используйте `autocut.py` — он считает намного быстрее.
* **Готовый файл выходит на 0,2–0,3 секунды длиннее заданного** — столько
  занимает хвост записи. Содержимое при этом ровно то, что вы выбрали.
  Если компьютер не успевает за записью, лишнего будет больше (подвисшие
  кадры) — приложение об этом предупредит и подскажет снизить качество до
  720p или частоту до 25 кадр/с.
* **Не все файлы открываются.** MP4 (H.264 + AAC) и WebM — почти всегда, MKV —
  как повезёт, HEVC/H.265, AC-3 и DTS обычно нет. Лечится перекодированием:
  `ffmpeg -i вход.mkv -c:v libx264 -c:a aac выход.mp4`.
* **MP4 умеют записывать не все браузеры.** В свежих Chrome и Edge — да, в
  остальных получится WebM (приложение предупредит).
* **Модель качается один раз.** tiny ≈ 40 МБ, base ≈ 80 МБ, small ≈ 250 МБ.
  Дальше она в кеше браузера.
* **Распознавание идёт долго, но страница остаётся живой.** Счёт вынесен в
  отдельный поток, поэтому во время работы можно листать страницу и менять
  настройки. Перед началом приложение честно пишет, сколько это займёт, и
  показывает, сколько кусков уже разобрано. Порядок величин на процессоре:
  модель `tiny` — примерно треть длительности клипа, `base` — около неё самой,
  `small` — раза в два с половиной дольше. Галочка WebGPU ускоряет в несколько
  раз. Если клип длинный, быстрее нарезать его на части и распознавать их
  по отдельности.
* **WebGPU заводится не на всех видеокартах.** Если драйвер откажет, приложение
  само перейдёт на процессор и скажет об этом.
* **Whisper ошибается** на музыке, шуме, шёпоте и наложенных голосах. Часть
  выдумок отсеивается автоматически — текст, попавший на тишину, и зацикленные
  повторы, — но субтитры всё равно стоит проверить глазами. Для этого и сделан
  редактор.
* **Пометки [СМЕХ] и [МУЗЫКА] — догадка по громкости, а не понимание звука.**
  Смех определяется по «рваности»: несколько всплесков в секунду с большой
  разницей между тихим и громким. Ровный громкий звук считается музыкой, тихий
  фоновый шум не подписывается никак. Аплодисменты или стук вполне могут
  получить не ту подпись — правьте в редакторе или снимите галочку «Помечать
  смех и музыку».
* **Нужен настольный браузер.** Рекомендуем Chrome или Edge.

# Часть 2. Конвейер автонарезки

Берёт фильм целиком и выдаёт папку готовых клипов с вшитыми субтитрами.

```bash
python autocut.py "фильм.mp4" --out clips --target-len 60 --min-len 30 --max-len 90 --lang ru --model small --crop 0.5
```

## Установка с нуля

### 1. Python 3.10 или новее

**Windows.** Скачайте с [python.org](https://www.python.org/downloads/) и при
установке **обязательно поставьте галочку «Add python.exe to PATH»** — без неё
команда `python` не заработает. Проверка:

```bash
python --version
```

**Linux (Ubuntu/Debian):**

```bash
sudo apt update && sudo apt install python3 python3-pip python3-venv
```

### 2. ffmpeg

Это отдельная программа, через `pip` она не ставится.

**Windows** — самое простое:

```bash
winget install Gyan.FFmpeg
```

После установки **закройте и откройте терминал заново**, иначе он не увидит
новый путь. Проверка: `ffmpeg -version`. Если winget недоступен, скачайте сборку с
[gyan.dev](https://www.gyan.dev/ffmpeg/builds/), распакуйте, например, в
`C:\ffmpeg` и добавьте `C:\ffmpeg\bin` в переменную среды PATH. Либо просто
пропишите полный путь в `config.yaml` → `tools.ffmpeg`.

**Linux:**

```bash
sudo apt install ffmpeg        # Ubuntu/Debian
sudo dnf install ffmpeg        # Fedora
```

### 3. Зависимости Python

```bash
pip install -r requirements.txt
```

Первый запуск скачает модель распознавания (tiny ≈ 75 МБ, small ≈ 500 МБ) —
дальше она берётся из кеша.

### 4. Видеокарта NVIDIA — по желанию

Ускоряет распознавание в разы. Нужны библиотеки CUDA:

```bash
pip install nvidia-cublas-cu12 nvidia-cudnn-cu12
```

Если их нет, `autocut.py` сам перейдёт на процессор и скажет об этом — ничего
не сломается.

## Как пользоваться

Самый простой вариант — всё по умолчанию:

```bash
python autocut.py "фильм.mp4"
```

Клипы окажутся в папке `clips`. Полезные флаги:

| Флаг | Что делает |
|---|---|
| `--out ПАПКА` | куда складывать клипы (по умолчанию `clips`) |
| `--target-len 60` | желаемая длина части в секундах |
| `--min-len 30` / `--max-len 90` | допустимый разброс длины |
| `--lang ru` | язык речи: `ru`, `en`, `auto` |
| `--model small` | `tiny` / `base` / `small` / `medium` / `large-v3` |
| `--crop 0.5` | сдвиг кадра при обрезке: `0` — левый край, `0.5` — центр, `1` — правый |
| `--jobs 4` | сколько частей рендерить одновременно |
| `--device cpu` | считать на процессоре, даже если есть видеокарта |
| `--no-label` | не рисовать надпись «Часть N» |
| `--no-subs` | не вшивать субтитры |
| `--no-sound-tags` | не подписывать `[СМЕХ]` и `[МУЗЫКА]` в паузах |
| `--limit 3` | сделать только первые 3 части — удобно, чтобы примериться |
| `--force` | перерисовать уже готовые части |
| `--force-subs` | перегенерировать `.ass`, затерев ручные правки |

### Что происходит внутри

1. **Звук.** ffmpeg вынимает дорожку в 16 кГц моно.
2. **Распознавание.** faster-whisper даёт тайминги по каждому слову. Транскрипт
   сохраняется рядом с фильмом (`фильм.transcript.small.ru.json`) — повторный
   запуск его переиспользует и не считает заново.
3. **Разбиение.** Фильм делится на части около `--target-len` секунд, но
   граница ставится **только в паузе речи** длиннее 0,6 с. Фраза никогда не
   рвётся посередине. Если подходящей паузы в допустимом окне нет, берётся
   самая длинная из имеющихся; если речи там нет вовсе — режется по времени.
4. **Субтитры.** На каждую часть пишется `.ass`: реплики по 3–4 слова,
   караоке-теги `\k`, жирный шрифт с чёрной обводкой на 78% высоты кадра.
   Заодно отсеивается текст, придуманный моделью поверх тишины (faster-whisper
   сам сообщает `no_speech_prob`, плюс проверка по громкости), а в паузах со
   звуком появляются `[СМЕХ]` и `[МУЗЫКА]`. Огибающая громкости сохраняется в
   кеше транскрипта, поэтому повторный запуск её не пересчитывает.
5. **Рендер.** ffmpeg точно вырезает отрезок с перекодированием (не по
   ключевым кадрам), обрезает в 9:16, масштабирует в 1080×1920, вшивает
   субтитры и надпись «Часть N». Части считаются параллельно.

### Что получается на выходе

```
clips/
  001.mp4          готовые клипы
  002.mp4
  001.ass          субтитры — можно править руками
  002.ass
  manifest.json    номер части, тайминги в фильме, текст реплик
```

`manifest.json` пригодится для заголовков и описаний: там лежит текст, который
звучит в каждом клипе.

### Правка субтитров руками

Файлы `.ass` — обычный текст, открываются в Блокноте или в
[Aegisub](https://aegisub.org/). **Уже существующий `.ass` конвейер не
перезаписывает**, так что можно смело править и перерендерить только видео:

```bash
python autocut.py "фильм.mp4" --out clips --force
```

Чтобы наоборот — выбросить правки и сгенерировать субтитры заново, добавьте
`--force-subs`.

### Прерывание и продолжение

Прервали на середине (Ctrl+C) или выключился свет — просто запустите ту же
команду ещё раз. Транскрипт возьмётся из кеша, готовые части пропустятся,
конвейер продолжит с места остановки.

### Настройка внешнего вида

Всё, что касается стиля, живёт в `config.yaml`: шрифт, размер, цвета обычного и
активного слова, толщина обводки, положение по вертикали, число слов в реплике,
текст надписи «Часть N», кодеки и битрейт. Флаги командной строки главнее
конфига.

Отдельно стоит знать про `subtitles.highlight_mode`:

* `karaoke` (по умолчанию) — теги `\k`, слова заливаются жёлтым одно за другим
  и остаются жёлтыми до конца реплики. Классический караоке-эффект;
* `current` — жёлтым горит только то слово, которое звучит прямо сейчас.
  Ближе к тому, как это выглядит в TikTok.

### Сколько это занимает времени

| Этап | На процессоре | С видеокартой NVIDIA |
|---|---|---|
| Распознавание двухчасового фильма, `small` | 30–60 минут | несколько минут |
| Рендер одной минутной части | 20–60 секунд | так же (упирается в процессор) |

Рендер идёт параллельно, так что общее время делится примерно на число ядер.
Совет: сначала прогоните с `--limit 3`, посмотрите на результат, а уже потом
запускайте весь фильм.

# Часть 3. Публикация

## YouTube Shorts

```bash
python upload_youtube.py clips --title "Название — часть {n} #shorts" --privacy public --per-day 5
```

### Настройка с нуля

1. Откройте [console.cloud.google.com](https://console.cloud.google.com/) и
   создайте новый проект (название любое).
2. **APIs & Services → Library** → найдите **YouTube Data API v3** → **Enable**.
3. **APIs & Services → OAuth consent screen** → тип **External** → заполните
   название приложения и свою почту → в разделе **Test users** добавьте тот
   аккаунт Google, на канал которого будете заливать.
4. **APIs & Services → Credentials** → **Create credentials** → **OAuth client
   ID** → тип приложения **Desktop app** → **Create** → **Download JSON**.
5. Положите скачанный файл рядом со скриптами и переименуйте в
   `client_secret.json`.

При первом запуске откроется браузер, вы войдёте в аккаунт и разрешите доступ.
Полученный токен сохранится в `youtube_token.json` — больше входить не
придётся.

### ⚠️ Важно: пока проект не прошёл проверку, ролики будут приватными

Это ограничение самого YouTube, а не скрипта. Пока ваш API-проект не прошёл
**audit** у Google, всё загруженное через API остаётся приватным, что бы вы ни
указали в `--privacy`. Ролик виден только вам; сделать его публичным можно
вручную в YouTube Studio.

Чтобы снять ограничение, нужно запросить проверку: в
[YouTube API Services — Audit and Quota Extension Form](https://support.google.com/youtube/contact/yt_api_form)
описать, что делает ваше приложение, и дождаться ответа Google. Обычно это
занимает недели. Для личного использования проще просто открывать ролики
вручную в Studio.

### Флаги

| Флаг | Что делает |
|---|---|
| `--title "…"` | шаблон заголовка; `{n}` — номер части, `{text}` — начало реплик |
| `--description "…"` | шаблон описания, те же подстановки |
| `--tags "shorts,нарезка"` | теги через запятую |
| `--privacy public\|unlisted\|private` | доступ (по умолчанию `private` — безопаснее) |
| `--per-day 5` | сколько роликов заливать за запуск |
| `--schedule 3h` | отложенная публикация с шагом: `90m`, `3h`, `1d` |
| `--start "2026-08-10 12:00"` | когда публиковать первый (по умолчанию через час) |
| `--dry-run` | показать план и ничего не загружать |

### Квота

Стандартная квота YouTube Data API — 10 000 единиц в сутки, одна загрузка стоит
1600, то есть **примерно 6 роликов в день**. Скрипт считает загрузки сам и
остановится, не пытаясь пробить лимит. Квота обнуляется в полночь по
тихоокеанскому времени (около 11:00 МСК).

Загруженное записывается в `clips/uploaded.json`, поэтому повторный запуск не
зальёт одно и то же дважды. **Не удаляйте этот файл**, иначе ролики уедут на
канал по второму разу.

## TikTok

```bash
python upload_tiktok.py clips --per-run 3
```

Видео уходит в **черновики** («инбокс») вашего аккаунта: в приложении TikTok
приходит уведомление, вы открываете черновик, правите описание и публикуете
одним касанием.

### Настройка с нуля

1. Зарегистрируйтесь на [developers.tiktok.com](https://developers.tiktok.com/)
   и создайте приложение (**Manage apps → Create an app**).
2. Добавьте продукт **Content Posting API** и включите режим
   **Direct Post / Inbox**.
3. Подключите **Login Kit** и получите `access_token` для своего аккаунта.
   Нужный scope — `video.upload` (для прямой публикации без подтверждения ещё
   и `video.publish`).
4. Положите ключи в переменные окружения:

   ```bash
   set TIKTOK_ACCESS_TOKEN=act.xxxxx        # Windows
   export TIKTOK_ACCESS_TOKEN=act.xxxxx     # Linux
   ```

   или в файл `tiktok_secret.json` рядом со скриптами:

   ```json
   {
     "client_key": "...",
     "client_secret": "...",
     "access_token": "act...",
     "refresh_token": "rft..."
   }
   ```

### ⚠️ Важно: автопостинг без подтверждения требует одобрения

Пока приложение не прошло **audit** у TikTok, доступен только режим черновиков:
опубликовать ролик всё равно придётся вручную одним касанием в приложении. Это
ограничение платформы. Прямая публикация (`video.publish`) открывается после
проверки приложения командой TikTok.

**Если ключей нет** — скрипт не падает с непонятной ошибкой, а честно говорит,
что публикация не настроена, и напоминает, что готовые клипы лежат в папке и их
можно загрузить руками.

# ⚖️ Авторские права — прочитайте обязательно

Фильмы, сериалы и мультфильмы защищены авторским правом. Нарезка чужого фильма
и публикация фрагментов **без разрешения правообладателя может нарушать закон**,
даже если вы не зарабатываете на этом.

Что произойдёт на практике:

* **Content ID на YouTube** распознаёт фрагменты фильмов автоматически, по
  видеоряду и по звуковой дорожке. Возможные последствия — от блокировки
  ролика в отдельных странах и передачи всех доходов правообладателю до
  **страйка**. Три страйка — канал удаляется.
* **TikTok и Instagram** тоже используют автоматическое распознавание и
  удаляют ролики, а при повторных нарушениях блокируют аккаунт.
* Правообладатель вправе потребовать удаления и обратиться в суд.

Свободное использование (цитирование, критика, пародия, обзор) в разных странах
трактуется по-разному и **не является автоматической защитой**. Короткая
длительность фрагмента сама по себе ничего не гарантирует, как и подпись
источника, и фразы вроде «права принадлежат правообладателю».

**Ответственность за то, какое видео вы загружаете и что делаете с
результатом, лежит целиком на вас.** ShortsVideoMaker — просто инструмент,
такой же, как любой видеоредактор.

## С каким видео проблем не будет

* **Своё собственное** — снятое вами, записи ваших стримов и эфиров.
* **Разрешённое правообладателем** — письменное разрешение или лицензия.
* **Общественное достояние.** Например, [архив Prelinger](https://archive.org/details/prelinger)
  и другие коллекции на [archive.org](https://archive.org/details/movies).
* **Свободные лицензии Creative Commons.** На YouTube есть фильтр по лицензии
  в расширенном поиске; есть [Wikimedia Commons](https://commons.wikimedia.org/),
  [Pexels](https://www.pexels.com/videos/), [Pixabay](https://pixabay.com/videos/).
  У каждой лицензии свои условия — обычно требуется указание автора, а часть
  запрещает коммерческое использование.

Указать источник в кадре помогает само приложение: галочка «Подпись источника»
в разделе «Стиль субтитров». Это то, чего ждут от цитирования и обзора, — но
само по себе разрешения на публикацию чужого видео оно не даёт.

## Чего в приложении нет и не будет

Приложение **не содержит средств обхода систем распознавания контента** —
ни зеркалирования кадра, ни сдвига скорости и высоты звука, ни наложения
рамок «под Content ID». Такие приёмы нужны ровно для одного: публиковать
чужое так, чтобы не заметили. Это не уменьшает нарушение, а лишь оттягивает
последствия — и обычно ухудшает картинку и звук.

Если ролик заблокировали по ошибке и вы уверены в своей правоте, у площадок
есть законный путь: оспаривание заявки Content ID в YouTube Studio и
встречное уведомление. Он работает и не создаёт новых проблем.

# Публикация сайта на GitHub Pages

Веб-редактор уже опубликован: источник — ветка `main`, папка `/ (root)`, сайт
живёт на https://mokydek.github.io/ShortsVideoMaker/. Каждый `git push` в `main`
обновляет его автоматически (сборка занимает около минуты).

Если Pages придётся включать заново:

1. Репозиторий → **Settings** → в левом меню **Pages**.
2. **Build and deployment** → **Source** → **Deploy from a branch**.
3. **Branch** → **`main`**, папка **`/ (root)`** → **Save**.
4. Через минуту-две обновите страницу — вверху появится ссылка на сайт.

> **Про тариф.** На бесплатном плане GitHub Pages работает только для
> **публичных** репозиториев. Если сделать репозиторий приватным, сайт
> отключится. Для приватного репозитория с Pages нужен GitHub Pro.

Файл `.nojekyll` в корне нужен, чтобы GitHub отдавал файлы как есть.

# Как это проверялось

**Веб-редактор** прогнан в headless-браузере через Playwright — и в Chromium, и
в настоящем Chrome, включая прогон против опубликованного сайта и прогон с
аппаратным ускорением. Проверялись: загрузка файла, установка границ отрезка
кнопками и полями, математика кадрирования 9:16, отрисовка кадров и субтитров
на canvas, снятие звука с ресемплингом в 16 кГц (по контрольному тону 1000 Гц —
чтобы тайминги не «поплыли» при ускоренном захвате), реальное распознавание
речи на русском и английском, экспорт, а также поведение при непроигрываемом
файле, видео без звука, недоступном CDN, заблокированном автозапуске и отказе
WebGPU.

Отдельно проверено, что нарезка по паузам действительно попадает в тишину: у
каждой границы измеряется громкость вокруг неё, и она должна быть нулевой.
Проверены также волна на таймлайне, отмена действий, горячие клавиши (включая
то, что они не перехватываются при вводе в поля), пресеты стиля и
перетаскивание границ мышью.

Работа с несколькими клипами: автонарезка даёт части нужной
длины и без дыр между ними; субтитры, сдвиг кадра и результат рендера у каждого
клипа свои и не протекают в соседние; очередь экспорта доводит до конца все
клипы и даёт каждому свой файл. Собранный в браузере ZIP проверен не только по
сигнатуре — архив распаковывается штатным распаковщиком Windows, и все видео
внутри открываются как 1080×1920 со звуком.

**Конвейер** прогнан целиком на трёхминутных тестовых видео, собранных ffmpeg
(`testsrc2` + синтезированная речь). Проверялись: клипы создаются, все 1080×1920
со звуком, длительности в заданном диапазоне, части стыкуются без дыр, манифест
сходится с файлами, повторный запуск ничего не пересчитывает. Вшивание
субтитров доказано сравнением одного и того же кадра из клипа с субтитрами и
из клипа, отрендеренного с `--no-subs`: около 20% отличающихся пикселей в
полосе субтитров при 0% в контрольной полосе. Отдельно проверено, что фильм без
единого слова речи не роняет программу и что подложенный руками `.ass`
действительно попадает в кадр. Скрипты публикации проверены до отправки:
планирование, отложенная публикация, учёт квоты, отказ от повторной загрузки и
понятные сообщения при отсутствии ключей.
