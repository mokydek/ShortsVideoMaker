# ShortsVideoMaker

Веб-приложение для нарезки коротких вертикальных клипов из фильмов, сериалов и
мультфильмов — с автоматическими субтитрами и караоке-подсветкой активного слова.

**Открыть сайт: https://mokydek.github.io/ShortsVideoMaker/**

Всё работает **прямо в браузере**: видео обрабатывается на вашем компьютере и
никуда не загружается. Ни сервера, ни регистрации, ни установки программ. Данные
нигде не сохраняются — при закрытии вкладки всё исчезает.

## Что умеет

| | |
|---|---|
| **Загрузка** | Кнопкой или перетаскиванием: MP4, WebM, MOV. Если браузер не умеет открывать файл — сразу честно об этом скажет. |
| **Обрезка** | Таймлайн с перемоткой, кнопки «Начало здесь» / «Конец здесь», точная подстройка числами, наглядная полоска отрезка и кнопка «Прослушать отрывок». |
| **Кадрирование** | Вертикаль **9:16** для Shorts / TikTok / Reels с ползунком сдвига кадра (какую часть широкого кадра оставить) или исходный формат. Предпросмотр — живой. |
| **Автосубтитры** | Распознавание речи моделью **Whisper** прямо в браузере (transformers.js). На выбор tiny / base / small, язык — авто, русский или английский. |
| **Редактор** | Список реплик: правится время начала, время конца и текст; строки можно добавлять и удалять. Реплики группируются по 3–4 слова — как в TikTok. |
| **Стиль** | Размер, положение по вертикали, цвет текста, цвет подсветки активного слова, тёмная подложка, ЗАГЛАВНЫЕ. Жирный шрифт с чёрной обводкой читается на любом фоне. |
| **Экспорт** | Кадры рисуются на canvas (1080×1920 или 720×1280) с вшитыми субтитрами, звук идёт через Web Audio. Результат — MP4, если браузер умеет, иначе WebM. |

## Как открыть локально

Скачайте репозиторий и **дважды щёлкните по `index.html`** — этого достаточно,
приложение состоит из одного файла.

Единственный нюанс: при открытии через `file://` некоторые браузеры не дают
загрузить модель распознавания речи с CDN. Всё остальное — обрезка,
кадрирование, ручные субтитры и экспорт — работает и так. Если нужны
автосубтитры, поднимите локальный сервер одной командой:

```bash
python -m http.server 8000
```

и откройте `http://localhost:8000/`. Либо через Node.js:

```bash
npx serve .
```

Сборка не нужна: ни npm, ни webpack, ни зависимостей в репозитории.

## Как это устроено

Один файл `index.html` — HTML, CSS и JavaScript инлайном. Внешняя зависимость
ровно одна: [transformers.js](https://github.com/huggingface/transformers.js)
с CDN jsDelivr, и она нужна только для распознавания речи.

1. **Звук.** Web Audio API: `MediaElementSource` → `ScriptProcessor` снимает
   сэмплы выбранного отрывка → микс в моно → ресемплинг в 16 кГц
   (`OfflineAudioContext`). Чтобы не ждать вхолостую, отрывок можно проигрывать
   в 2× или 4× с отключённым `preservesPitch`: сэмплы читаются как поток с
   частотой `sampleRate / speed`, поэтому темп и тон возвращаются к исходным.
2. **Распознавание.** Whisper через ONNX Runtime Web. Сначала запрашиваются
   пословные тайминги (`return_timestamps: 'word'`) — ради них берутся сборки
   `onnx-community/whisper-*_timestamped`, у которых в ONNX выгружено
   кросс-внимание декодера. Если такая сборка недоступна или модель не отдала
   пословные метки, приложение переключается на посегментные, а слова внутри
   сегмента раскладываются равномерно.
3. **Экспорт.** Видео проигрывается в реальном времени, каждый кадр рисуется на
   canvas с обрезкой и субтитрами, `canvas.captureStream()` и
   `MediaStreamDestination` собираются в один поток и пишутся `MediaRecorder`.

## Ограничения — прочитайте, чтобы не удивляться

* **Авторские права.** Фильмы, сериалы и мультфильмы защищены авторским правом.
  Ответственность за то, какое видео вы загружаете и что делаете с результатом,
  **лежит целиком на вас**. Приложение — просто инструмент, как видеоредактор.
* **Экспорт идёт в реальном времени.** 30 секунд клипа ≈ 30 секунд ожидания:
  браузер умеет писать видео только по мере воспроизведения. Не сворачивайте
  вкладку во время записи — фоновые вкладки притормаживают отрисовку.
* **Не все файлы открываются.** Браузер умеет только то, что умеет: MP4 (H.264 +
  AAC) и WebM открываются почти всегда, MKV — как повезёт, HEVC/H.265, AC-3 и
  DTS обычно не поддерживаются. Лечится перекодированием:
  `ffmpeg -i вход.mkv -c:v libx264 -c:a aac выход.mp4`.
* **MP4 умеют записывать не все браузеры.** В свежих Chrome и Edge — да, в
  остальных получится WebM (приложение об этом предупредит). WebM понимают
  YouTube, ВКонтакте и Telegram; для TikTok и Instagram файл лучше
  перекодировать в MP4.
* **Модель качается один раз.** tiny ≈ 40 МБ, base ≈ 80 МБ, small ≈ 250 МБ.
  Дальше она лежит в кеше браузера, и интернет для распознавания больше не
  нужен. Распознавание идёт на процессоре и на длинных отрывках заметно
  небыстрое; галочка WebGPU (Chrome/Edge) ускоряет его в разы.
* **WebGPU заводится не на всех видеокартах.** Некоторые драйверы собирают
  модель, но падают на самом счёте («Failed to run JSEP kernel», «no GPU data
  for input»). Приложение это ловит и само переезжает на процессор — результат
  тот же, только дольше. Если такое случилось, снимите галочку, чтобы не ждать
  дважды.
* **Whisper ошибается** на музыке, шуме, шёпоте и наложенных голосах. Субтитры
  почти всегда стоит проверить глазами — для этого и сделан редактор.
* **Нужен настольный браузер.** На телефоне интерфейс работает, но записи видео
  и распознавания на мобильных браузерах может не хватить памяти. Рекомендуем
  Chrome или Edge.

## Публикация на GitHub Pages

Публикация **уже включена**: источник — ветка `main`, папка `/ (root)`, сайт
живёт на https://mokydek.github.io/ShortsVideoMaker/. Каждый `git push` в `main`
обновляет его автоматически (сборка занимает около минуты).

Если Pages придётся включать заново — например, после смены настроек:

1. Откройте репозиторий → **Settings** → в левом меню **Pages**.
2. В блоке **Build and deployment** → **Source** выберите **Deploy from a branch**.
3. Ниже, в **Branch**, выберите ветку **`main`** и папку **`/ (root)`**,
   затем нажмите **Save**.
4. Подождите минуту-две и обновите страницу — вверху появится ссылка на сайт.

> **Важно про тариф.** На бесплатном плане GitHub Pages работает только для
> **публичных** репозиториев. Если сделать репозиторий приватным, сайт
> отключится, а API ответит «Your current plan does not support GitHub Pages for
> this repository». Для приватного репозитория с Pages нужен GitHub Pro.

Файл `.nojekyll` в корне нужен, чтобы GitHub отдавал файлы как есть и не
пытался собрать проект через Jekyll.

## Проверка качества

Приложение прогнано в headless-браузере через Playwright — и в Chromium, и в
настоящем Chrome. Проверялись: загрузка файла, метаданные, установка границ
отрезка кнопками и полями, математика кадрирования 9:16, отрисовка кадров и
субтитров на canvas, снятие звука с ресемплингом в 16 кГц (по контрольному тону
1000 Гц — чтобы тайминги не «поплыли» при ускоренном захвате), реальное
распознавание речи на русском и английском, экспорт (размер блоба больше нуля и
результат открывается в браузере), а также поведение при непроигрываемом файле,
видео без звука, недоступном CDN и заблокированном автозапуске. Ошибок в консоли
нет.
